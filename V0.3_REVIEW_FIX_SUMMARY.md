## 2. Findings Fixed

### P1-1 — Explicit build reused a stale Semantic Index

**Root Cause**

`build_knowledge_index.py` 调用 `KnowledgeService.prepare()`，而 `prepare()` 只要能加载
已有索引就返回成功，Knowledge Base 新增或删除文件时不会重建。

**Fix**

- 新增 typed `KnowledgeBuildResult` 和 `KnowledgeBackend.rebuild()`。
- Semantic/Legacy Backend 均从当前 corpus 完整 load、chunk、build、save。
- rebuild 成功后替换内存中的 store 和 cached retriever。
- build CLI 改为调用 `service.rebuild()` 并输出文档、页、Chunk 与 Index 路径。

**Files Changed**

- `backend/src/rag/base.py`
- `backend/src/rag/helloagents_backend.py`
- `backend/src/rag/legacy_faiss_backend.py`
- `backend/src/services/knowledge.py`
- `backend/scripts/build_knowledge_index.py`

**Tests Added**

- `test_semantic_rebuild_adds_new_document`
- `test_semantic_rebuild_removes_deleted_document`
- `test_rebuild_refreshes_cached_retriever`
- `test_legacy_rebuild_replaces_index_from_current_corpus`

### P1-2 — Global freshness polluted every TODO route

**Root Cause**

Router 将 research topic 和 TODO 字段拼接后产生单个 freshness flag，导致总主题中的
“2026 最新趋势”成为每个理论 TODO 的 hard boundary。

**Fix**

- 引入 `RoutingSignals.task_freshness_required` 和
  `global_freshness_context`。
- hard boundary 只使用 TODO title/intent/query 的 task freshness。
- global freshness 只进入结构化 Router prompt，作为软上下文。
- `RoutingDecision.freshness_required` 只表达单任务的新鲜度要求。

**Files Changed**

- `backend/src/services/retrieval_router.py`

**Tests Added**

- `test_global_freshness_does_not_force_theory_todo_hybrid`
- `test_fresh_todo_still_routes_web_or_hybrid`
- `test_llm_knowledge_route_is_not_overridden_by_global_freshness`
- `test_mixed_topic_routes_each_todo_independently`

### P2-1 — Catalog depended too heavily on filenames

**Root Cause**

Catalog 只有 document/type/pages，通用文件名无法表达实际领域。

**Fix**

- `KnowledgeDocumentInfo` 增加可空 `title`。
- Markdown 使用首个 H1；TXT 使用首个有效短行；PDF 使用第一页首个可信文本行。
- 无可靠内容时保持 `title=None`，不调用 LLM 编造。
- Router 综合 filename/title，并加入最小可解释的中英文机器人领域概念别名。

**Files Changed**

- `backend/src/rag/base.py`
- `backend/src/rag/catalog.py`
- `backend/src/services/retrieval_router.py`

**Tests Added**

- `test_catalog_extracts_markdown_and_text_titles`
- `test_catalog_extracts_pdf_title_from_first_page`
- `test_generic_filename_catalog_title_can_route_hybrid`

Legacy Runtime Index。

**Fix**

默认调试目录改为 `backend/vector_store/debug-legacy/`，并在 Knowledge Base README
明确说明隔离边界。

**Files Changed**

**Tests Added**

### P2-3 — Raw exceptions leaked through notice and SSE

**Root Cause**

Knowledge/Web notice、任务失败事件和最外层 streaming error 使用 `str(exc)`，可能暴露
Token、绝对路径或 Provider response。

**Fix**

- 新增集中管理的 user-safe messages。
- 服务端使用 `logger.exception()` 保存完整异常与堆栈。
- Knowledge/Web/Search provider notice、任务失败 SSE、HTTP/SSE 最外层错误只发送固定
  安全文本。

**Files Changed**

- `backend/src/services/user_messages.py`
- `backend/src/services/knowledge.py`
- `backend/src/services/research.py`
- `backend/src/services/search.py`
- `backend/src/agent.py`
- `backend/src/main.py`

**Tests Added/Updated**

### P2-4 — Web responses lacked a strict trust boundary

**Root Cause**

Search provider payloads were assumed to be dictionaries containing valid result objects. Malformed
items degraded through a broad exception handler, but unsafe URL schemes and oversized text could
still enter the Summarizer context and structured frontend sources.

**Fix**

- Normalize every provider response before context construction, including injected WebSearch
  implementations used by tests or integrations.
- Accept only `http`/`https` URLs with a hostname and no embedded credentials.
- Bound result count and text size, remove unsupported fields, and replace provider details with the
  existing user-safe notice.
- Derive the direct answer from the validated payload so a mismatched tuple value cannot bypass the
  trust boundary.

**Files Changed**

- `backend/src/services/search.py`
- `backend/src/services/research.py`

**Tests Added**

- `test_untrusted_web_payload_is_validated_before_context`
- `test_non_mapping_search_response_becomes_safe_empty_payload`
- `test_search_response_rejects_embedded_credentials_and_bounds_text`

### P2-5 — Generic Catalog terms caused cross-domain matches

**Root Cause**

Terms such as `industry`, `market`, and `report` were treated as document-domain aliases. A current
pharmaceutical-industry query could therefore route Hybrid against a humanoid-robotics report.

**Fix**

- Keep the deliberately small robotics/humanoid bilingual concept aliases.
- Exclude generic document and market vocabulary from filename/title token aliases.
- Preserve exact-title and domain-specific matches.

**Files Changed**

- `backend/src/services/retrieval_router.py`

**Tests Added**

- `test_generic_catalog_words_do_not_create_cross_domain_match`
- `test_generic_only_catalog_title_is_not_a_domain_match`

## 4. Index Freshness Demo

确定性 Fake Semantic Embedding 测试执行了真实文件与持久化生命周期：

```text
A.txt
  -> rebuild
  -> A searchable

add B.txt
  -> rebuild
  -> B is Top-1 and document_count changes 1 -> 2

delete B.txt
  -> rebuild
  -> B absent from store chunks
  -> B absent from metadata.json
  -> B absent from retrieval documents
```

同一 Backend 实例先执行 retrieve 缓存 Retriever，再修改 corpus 并 rebuild；测试确认
Retriever 对象已替换且第二次检索使用新索引。Legacy Backend 也验证了 Alpha corpus
替换为 Beta corpus 后只检索到 Beta。

## 8. Known Limitations

- No BM25, RRF, Reranker, Reflection Agent or automatic research loop.
- No frontend document upload, authentication or database.
- Relevance threshold remains model/corpus dependent and must be recalibrated after changes.
- PDF title extraction is deliberately simple and may return `None` for noisy first pages.
- Catalog bilingual aliases are intentionally small; they are not a general translation system.
- Windows/PyTorch model loading may require the documented sequential-load environment settings.
- Real LLM/Tavily end-to-end behavior remains unverified without explicit data-transfer authorization.
