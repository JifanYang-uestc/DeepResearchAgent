# V0.3 HelloAgents RAG Compatibility Spike

## Scope and environment

- Project baseline: `v0.2-knowledge-rag`
- Installed framework: `hello-agents==0.2.9`
- Runtime: Python 3.12, Windows, CPU
- Spike corpus: `backend/knowledge_base/test_facts.txt`
- Verified local model: `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`

The reproducible spike is `backend/scripts/v03_compatibility_spike.py`. It uses
the lower-level HelloAgents document, embedding, indexing, and search functions
with a tiny in-memory store, so no LLM, web API, or Qdrant server is involved.

## Compatibility results

1. `from hello_agents.tools import RAGTool` works with 0.2.9.
2. The installed base package does not include its RAG optional dependencies.
   Local semantic embeddings require `sentence-transformers`; the bundled
   Qdrant adapter requires a compatible `qdrant-client`.
3. HelloAgents' embedding provider defaults to DashScope, then attempts local
   transformer and TF-IDF fallbacks. This project will configure the local
   transformer explicitly so startup never silently depends on a paid API.
4. `LocalTransformerEmbedding` works on CPU. The verified multilingual model
   loaded through the `sentence-transformers` backend and produced 384-value
   vectors.
5. `RAGTool` constructs `QdrantVectorStore`; without a URL, that adapter connects
   to a server at `localhost:6333`.
6. `qdrant-client` supports persistent local mode through `QdrantClient(path=...)`,
   but HelloAgents 0.2.9's `QdrantVectorStore` does not expose that path. Its
   `**kwargs` are not forwarded to the client. A server is therefore required
   when using the bundled adapter unchanged.
7. `RAGTool.run({"action": "search"})` returns a human-readable string. The
   lower-level `create_rag_pipeline()["search"]` / `search_vectors()` API returns
   structured dictionaries.
8. The structured result contains `id`, `score`, and `metadata`. Metadata contains
   `content`, `source_path`, `memory_id`, offsets, namespace, and document IDs.
9. The bundled MarkItDown pipeline does not preserve PDF page numbers. It can
   supply document/content/score/chunk metadata, but cannot fully satisfy the
   existing citation contract by itself.
10. The lower-level embedding API is the best stable integration point for this
    project: reuse HelloAgents `LocalTransformerEmbedding`, retain the existing
    page-aware loader/chunker and FAISS persistence, and adapt results to the
    project's `RetrievalResult` / `EvidenceSource` models.

## Version findings

- `qdrant-client==1.19.0` is incompatible with HelloAgents 0.2.9 because the
  framework imports the removed `SearchRequest` symbol and then reports Qdrant
  as unavailable.
- `qdrant-client==1.15.1` imports successfully and direct persistent local mode
  works, but is not required by the selected default architecture.
- `sentence-transformers==6.0.0` was used for the spike. The project dependency
  remains minimally scoped to `sentence-transformers`; Qdrant is not a default
  runtime dependency.

## Semantic verification

The verified model produced the following cosine similarities in an isolated
CPU check:

- English ReAct description vs Chinese ReAct query: `0.7206`
- English ReAct description vs Chinese robotics-market query: `0.0468`

The HelloAgents lower-level spike indexed `test_facts.txt`, returned a structured
Top-1 result for `ResearchX-2026 使用什么 Vector Store？`, and the result contained
the expected `FAISS` fact with score `0.4252`.

These values only establish compatibility and semantic separation. The
production relevance threshold is calibrated separately against the actual
RAG/ReAct/Self-RAG corpus and is not inferred from this single check.

## Selected V0.3 backend

```text
KnowledgeService
  -> HelloAgentsSemanticBackend
     -> project PDF/TXT/Markdown loader
     -> project metadata-preserving chunker
     -> HelloAgents LocalTransformerEmbedding
     -> project persistent FAISS store
     -> project RetrievalResult
```

The V0.2 `HashingEmbedding + FAISS` implementation remains available as
`legacy_faiss` for regression, fallback, and comparison. Advanced HelloAgents
MQE/HyDE search remains disabled and no Qdrant server is required.

## Components not adopted

- `RAGTool.run()` search output: rejected because parsing its display string
  would be brittle.
- Bundled MarkItDown chunk pipeline: not used in production because page metadata
  is lost.
- Bundled Qdrant adapter: not used by default because it requires a server and
  its 0.2.9 API is version-sensitive.
- DashScopeEmbedding: optional by framework design, but not selected because the
  default must work locally without a paid embedding API.
- MQE, HyDE, cross-encoder reranking, graph ranking, and compression: outside the
  V0.3 scope.
